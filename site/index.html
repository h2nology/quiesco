02 / how it works

Fast because it never guesses.

Black-box tools can't see inside your app, so they sleep for a fixed time or poll the screen until something appears. Quiesco runs inside the e2e build and tracks every source of work. The instant the last one settles, the next step runs.

Example: after the test taps Save, the app is busy for 1.2 s, sending a request and re-rendering. When should the next step run?

03 / features

Everything a test needs, nothing in production.

F.01

Automatic synchronization

Network, timers, React scheduler, idle callbacks, native transitions and a frame-stability fallback. A sync timeout names what was still busy.

F.02

Real input, every platform

Touches and text through @quiesco/native on iOS and Android, Playwright on the web. The same test runs unchanged on all three.

F.03

Resets in ~200 ms

A soft reset (storage, your reset hooks, remount) before every test. Tag a test @hard-reset when it really needs a relaunch.

F.04

Backdoors

Set up state from the test without driving the UI: app.backdoor('loginAs', …). Log in once, test what matters.

F.05

Test UI and live progress

quiesco ui runs tests from the browser and shows each failure with its screenshot and element tree. The CLI keeps a progress bar on the last line.

F.06

Nothing in production

Without EXPO_PUBLIC_QUIESCO=1 the agent becomes a no-op stub and the native module is left out of the build. Checked in CI.

04 / quick start

Your first test in about ten minutes.

Bring an Expo app on SDK 55 or later and Node.js 24.

  1. Run npx quiesco init

    Installs dependencies, the config plugin, Metro setup, quiesco.config.mts and a first test.

  2. Wrap your root layout in <QuiescoRoot>

    One component turns on the agent in e2e builds only.

  3. Run npx quiesco test

    Against Chromium, an iOS simulator or an Android emulator.
