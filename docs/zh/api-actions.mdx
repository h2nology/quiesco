---
title: "操作"
description: "像用户一样点击、输入、滚动、滑动和拖动，返回上一页，以及打开深层链接。"
---

操作做的就是用户会做的事。在 `native` 模式下（App 包含 `@quiesco/native` 时的默认模式），它们是真实的触摸和键盘输入；在 `js` 模式下，它们改为调用组件的回调（见 [调用选项](./api#call-options)）。每个操作执行前后都会等待 App 空闲，并且需要恰好一个可见的目标（[查找元素](./api#finding-elements)）。

坐标使用逻辑单位：iOS 上为 pt，Android 上为 dp，web 上为 CSS px。

## 点击 {#tapping}

### `tap(target, options?)` {#tap}

```ts
tap(
  target: MatcherInput,
  options?: TapOptions,
): Promise<ElementSummary | undefined>
```

类型： [`MatcherInput`](./api-types#matcherinput) · [`TapOptions`](./api-types#tapoptions) · [`ElementSummary`](./api-types#elementsummary)

点击元素的中心。被滚动视图或 `overflow` 祖先裁掉一部分的元素，点击其可见部分的中心。

```ts
await app.tap('save');

// 元素内的一个点，从其左上角算起
await app.tap('map', { point: { x: 40, y: 120 } });
```

| 选项 | 默认值 | 含义 |
|---|---|---|
| `point` | 中心 | 元素自身坐标系中的 `{ x, y }`，代替其中心 |
| `timeoutMs` | `sync.timeoutMs`（10 秒） | 等待目标元素出现、App 空闲的最长时间 |
| `sync` | `true` | `false`：这次调用前后不等待 App 空闲（[通用选项](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：真实的触摸和键盘输入；`'js'`：调用组件的回调 |

## 文本输入 {#text-input}

### `type(target, text, options?)` {#type}

```ts
type(
  target: MatcherInput,
  text: string,
  options?: TypeOptions,
): Promise<ElementSummary | undefined>
```

类型： [`MatcherInput`](./api-types#matcherinput) · [`TypeOptions`](./api-types#typeoptions) · [`ElementSummary`](./api-types#elementsummary)

聚焦输入框，并在已有内容之后输入 `text`。在 `native` 模式下，文本经由系统的输入法输入，因此任何语言都可以。iOS 和 Android 上整段文本一次送达；web 上每个字符一次按键。

```ts
await app.type('email', 'ann@example.com');

```

| 选项 | 默认值 | 含义 |
|---|---|---|
| `perCharacter` | `false` | 逐字输入，让 App 收到每一次按键。调用会在最后等待空闲 |
| `intervalMs` | `80` | 配合 `perCharacter`：两个字符之间的间隔 |
| `timeoutMs` | `sync.timeoutMs`（10 秒） | 等待目标元素出现、App 空闲的最长时间 |
| `sync` | `true` | `false`：这次调用前后不等待 App 空闲（[通用选项](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：真实的触摸和键盘输入；`'js'`：调用组件的回调 |

## 滚动 {#scrolling}

### `scroll(target, direction, options?)` {#scroll}

```ts
scroll(
  target: MatcherInput,
  direction: Direction,
  options?: ScrollOptions,
): Promise<ElementSummary | undefined>
```

类型： [`MatcherInput`](./api-types#matcherinput) · [`Direction`](./api-constants#list) · [`ScrollOptions`](./api-types#scrolloptions) · [`ElementSummary`](./api-types#elementsummary)

滚动一个滚动视图。`'down'` 显示下方的内容。在 `native` 模式下，手指拖动时逐渐减速直到停下，所以内容移动约 `distance`，不会惯性滑动（会少掉系统的触摸 slop：iOS 约 10 pt，Android 约 7%）。

```ts

await app.scroll('feed', Direction.down, { distance: 300, from: { x: 0.5, y: 0.8 } });
```

| 选项 | 默认值 | 含义 |
|---|---|---|
| `distance` | — | 滚动多远，逻辑单位 |
| `from` | — | 手指的起点，在元素内归一化为 0–1 |
| `timeoutMs` | `sync.timeoutMs`（10 秒） | 等待目标元素出现、App 空闲的最长时间 |
| `sync` | `true` | `false`：这次调用前后不等待 App 空闲（[通用选项](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：真实的触摸和键盘输入；`'js'`：调用组件的回调 |

### `openUrl(url, options?)` {#openurl}

```ts
openUrl(url: string, options?: ActionOptions): Promise<void>
```

类型： [`ActionOptions`](./api-types#actionoptions)

打开一个深层链接：iOS 上在 App 内打开，Android 上用 `am start`，web 上通过地址栏。App 在后台时（`app.device.sendToBackground()`），像其他 App 那样从 App 外打开该链接；iOS 上会回答系统的「在 … 中打开？」确认。App 回到前台并空闲后 resolve。

```ts
await app.openUrl('myapp://todos/42');
await app.expectText('detail-title', 'Buy milk');
```

| 选项 | 默认值 | 含义 |
|---|---|---|
| `timeoutMs` | `sync.timeoutMs`（10 秒） | 等待 App 空闲的最长时间 |
| `sync` | `true` | `false`：这次调用前后不等待 App 空闲（[通用选项](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：真实的触摸和键盘输入；`'js'`：调用组件的回调 |

## 其他输入 {#other-inputs}

持有值的控件——开关、滑块、选择器、日期选择器——用 `setValue` 和 `adjustSlider` 设置，`accessibilityAction` 则执行屏幕阅读器的操作：见 [值控件](./api-value-controls)。

## `js` 模式下 {#js-mode}

当操作调用回调而不是触摸屏幕时：

- 点击某个点会按下该处最上层的元素；
- 点击没有 `onPress` 的开关时，通过 `onValueChange` 切换它；
- `pressKey` 调用 `onSubmitEditing` / `onKeyPress`；
- `scrollToEdge` 直接设置滚动偏移；
- `from` 被忽略；
- `drag` 不受支持，因为它需要真实的触摸。
