---
title: "测试 UI"
description: "用 quiesco ui 在浏览器里运行测试并实时查看：进度、失败以及 Quiesco 的证据。"
---

`quiesco ui` 会在浏览器里打开一个页面，列出项目里的所有测试。点一下就能运行全部测试、某个文件或单个测试，并实时查看运行情况：哪台设备正在跑什么、哪些通过哪些失败、错误信息，以及失败时 Quiesco 保存的证据（截图、元素树、空闲状态、日志）。

## 启动 {#starting}

<CodeGroup>
```sh pnpm
pnpm add -D @quiesco/ui
pnpm exec quiesco ui --platform web
pnpm exec quiesco ui --platform ios --config vitest.e2e.config.mts
```
```sh npm
npm i -D @quiesco/ui
npx quiesco ui --platform web
npx quiesco ui --platform ios --config vitest.e2e.config.mts
```
```sh bun
bun add -d @quiesco/ui
bunx quiesco ui --platform web
bunx quiesco ui --platform ios --config vitest.e2e.config.mts
```
```sh yarn
yarn add -D @quiesco/ui
yarn quiesco ui --platform web
yarn quiesco ui --platform ios --config vitest.e2e.config.mts
```
</CodeGroup>

它会打印页面地址并自动打开（`--no-open` 则不打开）。`--platform`、`--runner`、`--workers` 以及运行器自己的参数，含义和 [`quiesco test`](./cli#quiesco-test) 相同；运行器的参数用于每次运行，也用于列出测试。`--port N` 指定端口（默认使用空闲端口）。按 Ctrl-C 停止。

运行期间 Metro 开发服务器一直保持启动，所以从页面发起的运行不必等待它。运行器需要发送运行进度，这一点和[进度条](./cli#quiesco-test)相同：Vitest 需要 `quiescoPlugin()`，Jest 需要 preset 自带的 reporter，cucumber-js 无需任何设置（[测试运行器](./runners)）。

- **顶栏**：项目、运行器和平台（`todo-tutorial · vitest · web`）；搜索框；页面是否已连接到 `quiesco ui`；语言和主题；**停止**和**全部运行**。运行期间，“全部运行”会变成“运行中…”。
- **进度**：带进度环的已完成 / 总数、本次运行的状态和已用时间，以及通过、失败、跳过的测试数。有多个 worker 时，每台设备一条泳道，显示它正在跑的测试。

### 测试列表 {#test-list}

左栏列出测试文件及其中的测试，这是运行器在不执行测试的情况下列出的（与 [`quiesco list`](./cli#quiesco-list) 相同）。每个测试显示最近一次的结果和耗时；每个文件显示其中有多少测试已经运行，只要有一个失败就显示为红色。测试文件有改动时列表会自动更新；点 ↻ 按钮可以重新列出。

- **过滤**：全部、失败、运行中、跳过、通过，各自带有数量。
- **排序**：文件顺序、失败优先、最慢优先。
- **搜索**（在顶栏）：按测试名、文件或 `@tag`。
- **运行**：文件或测试旁边的 ▶ 只运行它。

键盘：`/` 搜索，测试树中用 ↑ ↓ ← → 移动，`r` 运行焦点所在的文件或测试，Ctrl/⌘ + Enter 运行全部，Ctrl/⌘ + . 停止（快捷键列在测试树下方）。页面支持 English、简体中文和日本語（跟随浏览器语言，也可以在顶栏切换），以及亮色和暗色两种主题（语言旁边的按钮）。

## 运行测试 {#running-tests}

同一时间只运行一次：设备只有一台（或每个 worker 一台），所以当前运行结束之前，运行按钮不可用。每次运行都和 `quiesco test` 一样启动运行器，再加上所选的测试：

| 运行器 | 一个文件 | 所选测试 |
|---|---|---|
| cucumber-js | `features/a.feature` | `features/a.feature:12:30`（Scenario 或 Examples 行的行号） |
| Vitest | `e2e/a.test.ts` | 每个测试一个 `e2e/a.test.ts:5` |
| Jest | `--runTestsByPath e2e/a.test.js` | 这些文件加上 `-t '^(full name\|…)$'` |

停止会结束运行器及其 worker。所选范围之外的测试保留各自最近一次的结果（Vitest 和 Jest 会把它们报告为跳过，页面会忽略这些报告）。

<Note>
cucumber-js 会把命令行给出的路径追加到配置的 `paths` 上，而不是替换它们。所以如果 `cucumber.mjs` 里写了 `paths`，运行单个测试时也会把这些路径一起跑。请不要在配置里写 `paths`（`quiesco init` 也不会写），改为在命令行上传入路径。
</Note>

## 安全 {#security}

页面只在 `127.0.0.1` 上提供。页面地址带有一个随机 token（首次访问后保存在 cookie 中）；Host 或 Origin 不符的请求会被拒绝。它只提供 artifacts 目录里的文件（证据）和已列出的测试文件（源码），不会提供项目里的其他文件。
