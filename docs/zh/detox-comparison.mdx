## Detox 的痛点与 Quiesco 的做法 {#detox-pain-points-and-what-quiesco-does-instead}

| 痛点（Detox） | Quiesco | 验证（2026-11-11） |
|---|---|---|
| 在 Expo SDK 56+ 的 Android 上网络同步失灵：只监听 OkHttp，而全局 `fetch` 是 `expo/fetch`（#4973） | agent 在 JS 中跟踪请求——全局 `fetch`、直接导入的 `expo/fetch`（Metro resolver）、`XMLHttpRequest`、WebSocket / EventSource 握手——直到响应体被读取完毕 | device: 等待 expo/fetch 的慢响应体, 离线时 expo/fetch 也失败, 等待 WebSocket 握手——iOS / Android / Web，只读取一次结果，不重试 |
| 随 React Native 版本更新而失效（RN 0.85.3 上 bridgeless 崩溃，#4963：反射访问私有字段） | 通过 DevTools 钩子从 React 自己的树中查找元素（一个文件，`fiber-adapter`），而不是从原生私有字段；原生模块只负责注入输入 | 整套测试运行于 React Native 0.88 / Expo SDK 58、bridgeless、三个平台 |
| 同步要么全开要么全关：无限动画、轮询或 socket 会让测试挂起；唯一的出路是全局关闭（#1513） | 运行时可按跟踪器、按元素控制（`sync.disableTracker`、`ignoreElements`、`ignoreUrls`），按调用传 `{ sync: false }`；打开的 WebSocket 从不计入，只计入其握手 | lifecycle: 运行时只关闭定时器同步，并忽略轮询计数; device: 等待 WebSocket 握手 |
| `expect` 不会等待；没有全局超时（#4885） | 断言会重试直到成立，默认 `sync.timeoutMs`，可按调用设置 `timeoutMs` | webview: 等待网页里稍后出现的结果（以及所有断言） |
| iOS 键盘吞掉第一次点击（#3399）；因为可见性检查，无法点击回车键（#4546） | 先收起遮住目标的键盘，`native` 跟踪器会等过 iOS 在键盘活动后的触摸屏蔽期；`pressKey('enter')` 无需键盘即可作用到输入框 | login / new-todo（在 iOS 上先输入再点击）；new-todo: 在标题框按回车也能保存; actions: 键盘按键与替换文本 |
| WebView 输入不可靠，Android 上有若干问题（#4886） | 在真实点击之后通过 `execCommand('insertText')` 输入；三个平台 API 相同 | webview: 在网页里输入名字后打招呼, 替换输入框里的文字——iOS / Android / Web |
| 许多能力仅限 iOS（pinch、启动时授予权限、生物识别、摇一摇、状态栏、语言区域、系统 UI、picker 列） | 每一项在 iOS 和 Android 上都可用，大多数在 Web 上也可用（见上表） | gestures、values、device、system |
| `atIndex` 的顺序在 iOS 与 Android 上不同；`toBeVisible` 固定为 75 % | `index` 在所有平台上都是渲染顺序；可见性 = 任一像素可见，`ratio` 可选 | 单元测试（agent query、visibility） |
| `setTimeout` 只等待最多 1.5 s，忽略 `setInterval`，且不可配置 | `sync.timerThresholdMs`（默认 1500）可配置；超时错误中会指出忙碌的定时器 | 单元测试（timer tracker） |
| 单独的测试 APK、ProGuard 规则、框架缓存 | 通过 config plugin 生成一个 e2e 构建（`EXPO_PUBLIC_QUIESCO=1`）；经验证生产构建中不含任何相关内容 | `scripts/check-prod-strip.mjs`（benchmarks.md） |
| 仅支持 Jest；产物文档「待完成」 | Cucumber / Jest / Vitest；产物有文档（api.md，Artifacts） | e2e/jest、e2e/vitest、features |

## 缺口 {#gaps}

决定不实现（2026-11-11），以及替代方案：

- **`selectApp`（一个测试中使用多个 App）：** 每个会话一个 App。请在各自的运行中分别测试每个 App。
- **`sendUserActivity` / `launchApp({ userActivity })`：** 不模拟 Handoff / Spotlight / Siri activity。链接（包括 universal link）通过 `openUrl` 或 `relaunch({ url })` 打开。
- **`resetContentAndSettings`：** 不提供抹掉整个模拟器的功能。`relaunch({ reinstall: true })` 移除 App 及其数据，`setPermission(p, 'reset')` 把权限恢复为 "not determined"，`clearKeychain()` 清空 keychain；场景改动过的设备状态（方向、外观、语言区域、位置、网络、状态栏、生物识别）会在下一个场景开始前自动还原。
- **`retries`：** 使用运行器自身的重试选项。
- **`by.traits`：** 使用 `{ role }` 和语义 `{ type }`。
