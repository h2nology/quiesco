---
title: "iOS 和 Android"
description: "构建 e2e App，在 iOS 模拟器和 Android 模拟器上运行同样的测试。"
---

原生平台的运行需要 App 的 e2e 构建（以 `EXPO_PUBLIC_QUIESCO=1` 构建，因此其中包含 agent和 `@quiesco/native`）：

<CodeGroup>
```sh pnpm
pnpm exec expo install expo-dev-client
pnpm exec quiesco build ios  # 或：pnpm exec quiesco build android
pnpm exec quiesco test --platform ios
```
```sh npm
npx expo install expo-dev-client
npx quiesco build ios       # 或：npx quiesco build android
npx quiesco test --platform ios
```
```sh bun
bunx expo install expo-dev-client
bunx quiesco build ios      # 或：bunx quiesco build android
bunx quiesco test --platform ios
```
```sh yarn
yarn expo install expo-dev-client
yarn quiesco build ios      # 或：yarn quiesco build android
yarn quiesco test --platform ios
```
</CodeGroup>

`quiesco build` 以 `EXPO_PUBLIC_QUIESCO=1` 运行 `expo prebuild` 和原生构建（面向模拟器的 `xcodebuild`、`gradlew assembleDebug`），并把 App 写到 `quiesco.config.mts` 中 `binaryPath` 指定的位置（生成的配置里已填好常用路径）。如果自上次构建以来 App 配置和依赖都没有变化，会跳过 Debug 构建；加 `--force` 则总是构建。当 dev client 需要 Metro 而 `devClient.metroUrl` 上没有响应时，`quiesco test` 会以 `EXPO_PUBLIC_QUIESCO=1` 启动 Metro，并在运行结束时停止它；你自己启动的 Metro 会直接使用（[配置](./api#configuration) 中的 `devServer`）。

在`devices` 中设置 Android Emulator / iOS Simulator（见 [配置](./api#configuration)）。在 CI 中，带 `EXPO_PUBLIC_QUIESCO=1` 的 EAS 构建配置（build profile）会产出同样的 e2e 构建；完整且经过测试的三平台配置见 [示例 App ](./example-app)。

各平台之间的差异（输入、权限、系统弹窗）见 [平台差异](./platforms)。
