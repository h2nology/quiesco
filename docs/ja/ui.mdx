---
title: "テスト UI"
description: "quiesco ui でブラウザからテストを実行し、進捗・失敗・Quiesco の証拠をリアルタイムで確認します。"
---

`quiesco ui`は、プロジェクトのすべてのテストを一覧するページをブラウザで開きます。クリックするだけで、すべてのテスト、ファイル単位、または1件のテストを実行でき、実行の様子をリアルタイムで確認できます。どのデバイスで何を実行しているか、どれが成功しどれが失敗したか、エラーの内容、そして失敗時にQuiescoが保存した証拠（スクリーンショット、要素ツリー、アイドル状態、ログ）です。

## 起動 {#starting}

<CodeGroup>
```sh pnpm
pnpm add -D @quiesco/ui
pnpm exec quiesco ui --platform web
pnpm exec quiesco ui --platform ios --config vitest.e2e.config.mts
```
```sh npm
npm i -D @quiesco/ui
npx quiesco ui --platform web
npx quiesco ui --platform ios --config vitest.e2e.config.mts
```
```sh bun
bun add -d @quiesco/ui
bunx quiesco ui --platform web
bunx quiesco ui --platform ios --config vitest.e2e.config.mts
```
```sh yarn
yarn add -D @quiesco/ui
yarn quiesco ui --platform web
yarn quiesco ui --platform ios --config vitest.e2e.config.mts
```
</CodeGroup>

ページのアドレスを表示し、ブラウザで開きます（`--no-open`を付けると開きません）。`--platform`、`--runner`、`--workers`、ランナー自身の引数の意味は[`quiesco test`](./cli#quiesco-test)と同じです。ランナーの引数は毎回の実行とテストの一覧の両方に使われます。`--port N`でポートを指定します（デフォルトは空いているポート）。Ctrl-Cで停止します。

起動している間はMetro開発サーバーを動かしたままにするので、ページから始めた実行がその起動を待つことはありません。ランナーは[進捗バー](./cli#quiesco-test)と同じく進捗を送る必要があります。Vitestは`quiescoPlugin()`、Jestはプリセットのレポーターが必要で、cucumber-jsは設定不要です（[テストランナー](./runners)）。

## ページ {#the-page}

- **進捗** —— 完了数 / 総数、成功・失敗・スキップの件数、経過時間。ワーカーが複数あるときは、デバイスごとに実行中のテストを表示するレーンが並びます。
- **テスト** —— ランナーがテストを実行せずに一覧したファイルとテスト（[`quiesco list`](./cli#quiesco-list)と同じ一覧）と、それぞれの直近の結果。名前・ファイル・タグで検索し、状態で絞り込み、失敗や所要時間で並べ替えられます。テストファイルを変更すると一覧も更新されます。
- 選択したテストの**詳細** —— **レポート**：エラー、期待値と実際の値の差分、スタック。**証拠**：アサーションの対象要素を枠で示した失敗時のスクリーンショット、要素ツリー、アイドル状態、ログ。**コンソール**：テスト自身の出力（Vitestはテストごとにコンソール出力を、cucumber-jsは`this.log()`を保存します）とランナーの出力。**ソース**：読み取り専用のテストファイル。テストの行と失敗した行に印が付きます。

キーボード：`/`で検索、ツリーでは↑ ↓ ← →で移動、`r`でフォーカスしているファイルやテストを実行、Ctrl/⌘ + Enterですべて実行、Ctrl/⌘ + .で停止します。ページはEnglish、简体中文、日本語に対応し（ブラウザの言語、またはヘッダーで選んだ言語）、ダークとライトのテーマがあります。

## テストの実行 {#running-tests}

実行は同時に1回だけです。デバイスは1台（またはワーカーごとに1台）なので、実行中は実行ボタンが使えません。実行のたびに`quiesco test`と同じ方法でランナーを起動し、選んだテストを指定します。

| ランナー | ファイル単位 | 選んだテスト |
|---|---|---|
| cucumber-js | `features/a.feature` | `features/a.feature:12:30`（ScenarioまたはExamplesの行番号） |
| Vitest | `e2e/a.test.ts` | テストごとに`e2e/a.test.ts:5` |
| Jest | `--runTestsByPath e2e/a.test.js` | 対象のファイルと`-t '^(full name\|…)$'` |

停止するとランナーとそのワーカーが終了します。選んだテスト以外は直近の結果をそのまま残します（VitestとJestはそれらをスキップとして報告しますが、ページは無視します）。

<Note>
cucumber-jsは、コマンドラインで渡したパスを設定の`paths`に置き換えるのではなく追加します。そのため`cucumber.mjs`に`paths`があると、1件のテストを実行してもそれらのパスまで実行されます。設定には`paths`を書かず（`quiesco init`も書きません）、パスはコマンドラインで渡してください。
</Note>

## セキュリティ {#security}

ページは`127.0.0.1`でのみ提供されます。アドレスにはランダムなトークンが含まれ（初回アクセス後はCookieに保存）、ホストやオリジンが一致しないリクエストは拒否されます。提供するファイルはartifactsディレクトリ内のもの（証拠）と一覧したテストファイル（ソース）だけで、プロジェクトのそれ以外のファイルは提供しません。
