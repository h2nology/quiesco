```sh
npx quiesco <command> [options]
```

## `quiesco init` {#quiesco-init}

ExpoプロジェクトにQuiescoをセットアップします。各手順で何をしたかを報告します。既存のファイルは決して上書きしません。Quiescoが安全に変更できないファイルについては、追加すべき内容を表示します。

1. プロジェクトのパッケージマネージャー（ロックファイルから判断したnpm、pnpm、yarn、bunのいずれか）でパッケージをインストールします。`@quiesco/agent`と`@quiesco/native`はdependenciesに、`quiesco`、`@quiesco/core`、`@quiesco/cucumber`、`@quiesco/expo-plugin`、`@cucumber/cucumber`（Web向けには`@quiesco/web`と`playwright`も）はdevDependenciesに入ります。Quiescoのパッケージは`init`を実行したCLIと同じバージョンでインストールします（`npx quiesco@0.4.0 init`なら0.4.0）。そのため、書き込むスクリプトとインストールされたCLIが一致します。インストール後、`init`はインストールされたバージョンを読み直し、食い違いがあれば実行すべきインストールコマンドを示して停止します（パッケージマネージャーがキャッシュの古いレジストリ情報を使った場合など）。
2. `app.json`のpluginsに`@quiesco/expo-plugin`を追加し、足りないアプリIDも書き込みます。`ios.bundleIdentifier`、`android.package`（どちらも`com.anonymous.<slug>`）と`scheme`（slug）です。これでビルドされるアプリと`quiesco.config.mts`が同じアプリを指します。これらがないと`expo prebuild`は独自の既定値を使い、その値はiOSとAndroidで異なります。`app.config.js` / `.ts`を使っているプロジェクトでは、書き込まずに自分で行う作業として示します。
3. `withQuiesco()`を使った`metro.config.js`を作成します（既存のものがあれば、ラップする方法を説明します）。
4. エントリーファイルの最初のimportを`@quiesco/agent`にします。Expo Routerのアプリには`index.ts`（`import '@quiesco/agent'; import 'expo-router/entry';`）と`"main": "index.ts"`を用意します。エントリーがローカルのコンポーネントを登録している場合（ブランクテンプレートのような`registerRootComponent(App)`）は、`init`がエントリーでそのコンポーネントを`<QuiescoRoot>`でラップします。
5. `quiesco.config.mts`（バンドルID、パッケージ名、スキームは`app.json`から取得）、`cucumber.mjs`、`features/support/quiesco.ts`、ステップ付きの最初のfeature、`e2e:*`スクリプトを書き出し、`tsconfig.json`に`"allowImportingTsExtensions": true`を追加します（stepファイル同士は`.ts`付きでimportします。[stepファイルはコンパイルされない](./driver-pattern#type-stripping)を参照）。

| オプション | |
|---|---|
| `--platforms ios,android,web` | セットアップするプラットフォーム。デフォルトはiOSとAndroidで、`react-native-web`がインストールされていればWebも加わります |
| `--packages <dir>` | `<dir>`内の`.tgz`ファイル（`pnpm pack`の出力）からQuiescoをインストールし、パッケージ間の依存もそれらに固定します |
| `--skip-install` | インストールコマンドを表示するだけにします |
| `--upgrade` | 古いバージョンでセットアップしたプロジェクトをこのバージョンに上げます（[プロジェクトのアップグレード](#quiesco-init-upgrade)） |
| `--dry-run` | `--upgrade`と一緒に使い、変更内容を示すだけで変更はしません |

`init`が行わず、自分で行う作業：テストIDの付与と、Expo Routerアプリ（および安全に変更できないその他のエントリー）でルートレイアウトを`<QuiescoRoot>`でラップすること。残った作業は`init`が一覧で示します。

### プロジェクトのアップグレード {#quiesco-init-upgrade}

```sh
npx quiesco@latest init --upgrade            # バージョンを指定するならquiesco@0.4.1
npx quiesco@latest init --upgrade --dry-run  # 変更内容を示すだけ
```

古い`quiesco init`でセットアップしたプロジェクトを、実行したCLIのバージョンに上げます。

1. すべてのQuiescoパッケージをそのバージョンでインストールします。`init`が追加しないパッケージ（`@quiesco/steps`など）も対象です。`init`と同じく、インストール後にバージョンを読み戻して確かめます。`@cucumber/cucumber`と`playwright`には触れません。
2. cucumberの設定から`paths: ['features/**/*.feature']`を削除します。古いバージョンが書き込んでいた行で、これがあると`quiesco test features/x.feature`がすべてのfeatureを実行していました。
3. `tsconfig.json`に`"allowImportingTsExtensions": true`を追加します。
4. `app.json`に足りないアプリIDを書き込み（上の手順2と同じ）、`quiesco.config.mts`の`// TODO: expo.…`のプレースホルダーをその値に置き換えます。
5. 足りない`e2e:*`スクリプトを追加し、`registerRootComponent(App)`を`<QuiescoRoot>`でラップします。

変更はすべて一覧で示します。安全に変更できないもの（自分で設定した`paths`、コメント入りの`tsconfig.json`、`app.config.js` / `.ts`）は、対処法と一緒に示します。もう一度実行しても何も変わりません。プラットフォームは`quiesco.config.mts`（または`--platforms`）から決まります。実行後は`npx quiesco doctor`を実行してください。

## `quiesco build` {#quiesco-build}

```sh
npx quiesco build ios
npx quiesco build android --force
```

e2eアプリをビルドし（`EXPO_PUBLIC_QUIESCO=1`付きの`expo prebuild`の後、シミュレーター向けの`xcodebuild`、または`gradlew assembleDebug` / `assembleRelease`）、`apps.<platform>.binaryPath`に書き出します。iOSでは、derived dataのパス、構成、スキームをそのパス（`<dir>/Build/Products/<Configuration>-iphonesimulator/<Name>.app`）から読み取ります。前回からアプリの設定と依存関係（インストール済みのバージョンを含む）が変わっておらず、ビルドが残っていれば、Debugビルドは省略します。`--force`を付けると必ずビルドします。ReleaseビルドはJSバンドルを含むため、常にビルドします。

## `quiesco test` {#quiesco-test}

```sh
npx quiesco test --platform web
npx quiesco test --platform android --tags @smoke features/login.feature
npx quiesco test --platform ios --runner vitest --config vitest.e2e.config.mts
npx quiesco test --platform web --runner jest e2e/todo.test.js
npx quiesco test --platform web -- --tags @debug
npx quiesco test --help
```

`QUIESCO_PLATFORM`を設定し、プロジェクトのテストランナーを実行します。ランナーは`cucumber-js`（デフォルト）、`jest`、`vitest run`のいずれかで（`--runner`）、それ以外の引数はすべてそのままランナーに渡します。`--`より後ろの引数もランナーに渡し、`--`自体は取り除きます。そのため、その後ろに書いたQuiescoのオプション名はランナーのものとして扱われます（`quiesco test -- --help`はランナーのヘルプを表示します）。`--workers N`はN個のワーカーを、それぞれ専用のデバイスで実行します（[parallel.md](./parallel)）。cucumber-jsでは`--parallel N`、Jestでは`--maxWorkers N`、Vitestでは`--fileParallelism --maxWorkers N`に変換されます（ランナー自身のフラグも使えます）。

ターミナルでは、ランナーの出力がその上に流れていく間、最終行に進捗バーを表示し続けます。完了数 / 総数、成功・失敗・スキップの件数、経過時間、実行中のテスト（ワーカーが複数あるときはデバイスごと）です。進捗はランナーが送ります。cucumber-jsには`quiesco test`が`@quiesco/cucumber`のフォーマッターを自動で追加し、Vitestには`quiescoPlugin()`が必要で、Jestではプリセットが用意します（[Jest と Vitest](./runners)）。送られてこない場合は、終了時に何を追加すればよいかを表示します。`--no-progress`または`QUIESCO_PROGRESS=0`で進捗バーを消せます。CIや、出力がターミナルでない場合も表示しません。終了コードはランナーのものです。

アプリがMetroからJSを読み込み（`devClient.metroUrl`、または`apps.web.url`）、そこで何も応答しない場合、`quiesco test`は`EXPO_PUBLIC_QUIESCO=1`付きでMetroを起動し（`npx expo start --port <port>`、出力は`artifacts/metro.log`）、準備ができるまで待ち、ランナーが終わると停止します（Ctrl-Cのときも）。すでに動いているMetroはそのまま使います。設定の`devServer`でコマンドとタイムアウトを変えたり、この動作を止めたり（`autoStart: false`）できます。ランナーを直接実行した場合（`npx cucumber-js`）はMetroを起動しません。

## `quiesco ui` {#quiesco-ui}

```sh
npx quiesco ui --platform web
npx quiesco ui --platform ios --runner vitest --config vitest.e2e.config.mts --port 5173
npx quiesco ui --help
```

[テスト UI](./ui)をブラウザで開きます。プロジェクトのテストを一覧し、クリックだけですべて / ファイル単位 / 1件のテストを実行でき、進捗と、失敗およびその証拠をリアルタイムで確認できます。プロジェクトに`@quiesco/ui`が必要です。`--platform`、`--runner`、`--workers`、ランナーの引数は`quiesco test`と同じです。`--port N`でポートを指定し、`--no-open`ではブラウザを開きません。起動中はMetroを動かしたままにします。Ctrl-Cで停止します。

## `quiesco list` {#quiesco-list}

```sh
npx quiesco list
npx quiesco list features/login.feature
npx quiesco list --runner vitest --config vitest.e2e.config.mts --json
```

ランナーが実行するテストを、ファイルごとに行番号付きで一覧します。テストは実行せず、デバイスも起動しません。cucumber-jsはフォーマットを外したドライランを行い（レポートファイルはそのまま）、Vitestはテストファイルを解析し、JestはQuiescoのテスト環境とプロジェクトのglobal setupを使わずにテストを収集します（setup filesは実行されます）。`--json`は、進捗バーとテスト UIが使うテストIDを含む一覧を出力します。何も一覧できなかった場合の終了コードは1です。

## `quiesco devices` {#quiesco-devices}

```sh
npx quiesco devices            # Quiescoが並列ワーカー用に作成したシミュレーター / AVD
npx quiesco devices --prune    # それらをシャットダウンして削除する
```

`"<name> (Quiesco N)"`シミュレーターと`<avd>_quiesco_N` AVDを一覧表示します（起動中のものには`[running]`が付きます）。`--prune`はそれらを削除します。次の並列実行で再作成されます。自分で用意したデバイスには一切触れません。

## `quiesco doctor` {#quiesco-doctor}

```sh
npx quiesco doctor                 # quiesco.config.mtsで設定したすべてのプラットフォーム
npx quiesco doctor --platform ios
```

Node.js、プロジェクトのセットアップ（パッケージ、すべてのQuiescoパッケージが同じバージョンか、package.jsonのスクリプトにある`quiesco <command>`がすべて存在するか、config plugin、Metroの`withQuiesco()`、エントリーの最初のimportとしてのエージェント、`<QuiescoRoot>`、設定ファイル）、アプリID（`quiesco.config.mts`が`app.json`やビルドと一致しているか、`init`が残したプレースホルダー）、古いバージョンが書き込んだ設定（cucumberの設定の`paths`、`allowImportingTsExtensions`なしでstepファイルが`.ts`をimportしている）、プラットフォームのツール（シミュレーター、adbとAVD、PlaywrightのChromium）、アプリのビルド、ポートをチェックします。問題ごとに修正方法を示します。古いセットアップに足りないものの多くは`npx quiesco@latest init --upgrade`で直せます。必須のチェックが失敗すると終了コード1で終わります。警告と補足（ℹ️、たとえば`e2e:build:*`スクリプトがない）では失敗しません。

## `quiesco tree` {#quiesco-tree}

```sh
npx quiesco tree                   # 実行中のアプリに接続する
npx quiesco tree --launch --platform android
npx quiesco tree --json > tree.json
```

アプリが表示している画面の要素ツリーを、要素ごとに型、`#testID`、テキスト、`[role]`付きで出力します。ステップで使うマッチャーを探すのに役立ちます。

```
RCTView #todos-screen
  RCTText #greeting "a@example.com"
  RCTScrollView #todo-list
    RCTText #todo-empty "No todos yet"
  RCTView #add-todo [button]
    RCTText "New"
```

デフォルトではホストサーバーだけを起動し、すでに動いているアプリを待ちます（手動で起動したe2eビルドや、テスト実行後に残ったアプリは数秒以内に再接続します）。そのため、自分で遷移した画面をそのまま確認できます。`--launch`を付けると、テスト実行と同じようにデバイスを起動してからアプリを起動します。`--timeout <ms>`でアプリを待つ時間を設定します。
