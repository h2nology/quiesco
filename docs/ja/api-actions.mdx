---
title: "アクション"
description: "ユーザーと同じようにタップ、入力、スクロール、スワイプ、ドラッグし、前の画面に戻り、ディープリンクを開く。"
---

アクションはユーザーが行う操作を再現します。`native`モード（アプリに`@quiesco/native`がある場合のデフォルト）では実際のタッチとキーボード入力です。`js`モードでは代わりにコンポーネントのコールバックを呼びます（[呼び出しのオプション](./api#call-options)を参照）。どのアクションも前後でアプリがアイドルになるのを待ち、表示されているターゲットがちょうど1つ必要です（[要素を見つける](./api#finding-elements)）。

座標は論理単位です（iOSではpt、Androidではdp、WebではCSS px）。

## タップ {#tapping}

### `tap(target, options?)` {#tap}

```ts
tap(
  target: MatcherInput,
  options?: TapOptions,
): Promise<ElementSummary | undefined>
```

型： [`MatcherInput`](./api-types#matcherinput) · [`TapOptions`](./api-types#tapoptions) · [`ElementSummary`](./api-types#elementsummary)

要素の中心をタップします。スクロールビューや`overflow`の祖先に一部が切り取られた要素は、見えている部分の中心をタップします。

```ts
await app.tap('save');

// 要素内の一点。左上隅から
await app.tap('map', { point: { x: 40, y: 120 } });
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `point` | 中心 | 中心の代わりにタップする、要素自身の座標系での`{ x, y }` |
| `timeoutMs` | `sync.timeoutMs`（10秒） | 対象の要素が現れ、アプリがアイドルになるまで待つ最大時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアプリのアイドルを待ちません（[共通オプション](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：実際のタッチとキーボード入力、`'js'`：コンポーネントのコールバックを呼び出します |

## テキスト入力 {#text-input}

### `type(target, text, options?)` {#type}

```ts
type(
  target: MatcherInput,
  text: string,
  options?: TypeOptions,
): Promise<ElementSummary | undefined>
```

型： [`MatcherInput`](./api-types#matcherinput) · [`TypeOptions`](./api-types#typeoptions) · [`ElementSummary`](./api-types#elementsummary)

入力欄にフォーカスし、既にある内容の後ろに`text`を入力します。`native`モードではテキストがシステムのIMEを経由するので、どの言語でも入力できます。iOSとAndroidではテキスト全体が一度に届き、Webでは1文字ごとに1キーが送られます。

```ts
await app.type('email', 'ann@example.com');

// 1文字ずつ：デバウンス付き検索、入力マスク、onKeyPress向け

```

| オプション | デフォルト | 意味 |
|---|---|---|
| `perCharacter` | `false` | 1文字ずつ入力し、アプリがキー入力を1回ずつ受け取るようにする。呼び出しは最後にアイドルを待つ |
| `intervalMs` | `80` | `perCharacter`のとき：文字と文字の間隔 |
| `timeoutMs` | `sync.timeoutMs`（10秒） | 対象の要素が現れ、アプリがアイドルになるまで待つ最大時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアプリのアイドルを待ちません（[共通オプション](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：実際のタッチとキーボード入力、`'js'`：コンポーネントのコールバックを呼び出します |

## スクロール {#scrolling}

### `scroll(target, direction, options?)` {#scroll}

```ts
scroll(
  target: MatcherInput,
  direction: Direction,
  options?: ScrollOptions,
): Promise<ElementSummary | undefined>
```

型： [`MatcherInput`](./api-types#matcherinput) · [`Direction`](./api-constants#list) · [`ScrollOptions`](./api-types#scrolloptions) · [`ElementSummary`](./api-types#elementsummary)

スクロールビューをスクロールします。`'down'`で下のコンテンツが現れます。`native`モードでは指をドラッグして徐々に減速させて止めるので、慣性スクロールせずにコンテンツがおよそ`distance`だけ動きます（システムのタッチスロップの分だけ短くなります。iOSで約10pt、Androidで約7%）。

```ts
await app.scroll('feed', Direction.down);

await app.scroll('feed', Direction.down, { distance: 300, from: { x: 0.5, y: 0.8 } });
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `distance` | — | スクロールする距離（論理単位） |
| `from` | — | 指の開始点。要素内で0–1に正規化した位置 |
| `timeoutMs` | `sync.timeoutMs`（10秒） | 対象の要素が現れ、アプリがアイドルになるまで待つ最大時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアプリのアイドルを待ちません（[共通オプション](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：実際のタッチとキーボード入力、`'js'`：コンポーネントのコールバックを呼び出します |

## ナビゲーション {#navigation}

### `goBack(options?)` {#goback}

```ts
goBack(options?: ActionOptions): Promise<void>
```

型： [`ActionOptions`](./api-types#actionoptions)

各プラットフォームでユーザーが行うのと同じ方法で前の画面に戻ります。Androidは戻るボタン（キーボードは先に閉じる）、Webはブラウザーの戻る、iOSはナビゲーションバーの戻るボタン、なければ左端からのスワイプです。Expo Routerを使うアプリでは、ルートが変わらなければ失敗します。

```ts
await app.tap({ text: 'Buy milk' });
await app.goBack();
await app.expectVisible('todo-list-screen');
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `timeoutMs` | `sync.timeoutMs`（10秒） | アプリがアイドルになるまで待つ最大時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアプリのアイドルを待ちません（[共通オプション](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：実際のタッチとキーボード入力、`'js'`：コンポーネントのコールバックを呼び出します |

### `pressBack(options?)` {#pressback}

```ts
pressBack(options?: ActionOptions): Promise<void>
```

型： [`ActionOptions`](./api-types#actionoptions)

Androidの戻るボタン、WebではブラウザーのBackです。iOSでは使えません（`ACTION_NOT_SUPPORTED`）。どのプラットフォームでも動くテストには`goBack()`を使ってください。

```ts
// Android：戻るボタンでボトムシートを閉じる
await app.pressBack();
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `timeoutMs` | `sync.timeoutMs`（10秒） | アプリがアイドルになるまで待つ最大時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアプリのアイドルを待ちません（[共通オプション](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：実際のタッチとキーボード入力、`'js'`：コンポーネントのコールバックを呼び出します |

### `openUrl(url, options?)` {#openurl}

```ts
openUrl(url: string, options?: ActionOptions): Promise<void>
```

型： [`ActionOptions`](./api-types#actionoptions)

ディープリンクを開きます。iOSではアプリ内で、Androidでは`am start`で、Webではアドレスバーで開きます。アプリがバックグラウンドにあるとき（`app.device.sendToBackground()`）は、ほかのアプリからと同じようにアプリの外からリンクを開きます。iOSではシステムの「“…”で開きますか？」に答えます。アプリが前面に来てアイドルになった時点で解決します。

```ts
await app.openUrl('myapp://todos/42');
await app.expectText('detail-title', 'Buy milk');
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `timeoutMs` | `sync.timeoutMs`（10秒） | アプリがアイドルになるまで待つ最大時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアプリのアイドルを待ちません（[共通オプション](./api#call-options)） |
| `mode` | `actions.mode` | `'native'`：実際のタッチとキーボード入力、`'js'`：コンポーネントのコールバックを呼び出します |

## その他の入力 {#other-inputs}

値を持つコントロール（スイッチ、スライダー、ピッカー、日付ピッカー）は`setValue`と`adjustSlider`で設定し、`accessibilityAction`はスクリーンリーダーのアクションを実行します。[値コントロール](./api-value-controls)を参照してください。

## `js`モードでは {#js-mode}

アクションが画面をタッチする代わりにコールバックを呼ぶ場合：

- 座標を指定したタップは、その位置の最前面の要素を押します。
- `onPress`のないスイッチへのタップは、`onValueChange`で切り替えます。
- `pressKey`は`onSubmitEditing` / `onKeyPress`を呼びます。
- `scrollToEdge`はスクロールオフセットを設定します。
- `from`は無視されます。
- `drag`は実際のタッチが必要なため、サポートされません。
