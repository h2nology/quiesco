テストは1つのオブジェクト、**ドライバー**を通してアプリを操作します。ドライバーはユーザーと同じようにタップ、入力、スクロールを行い、画面に何があるかを確認し、セットアップのためにアプリの内部にも手を伸ばします。このセクションでは、すべてのメソッドをトピックごとに1ページずつ、それぞれ例を付けて説明します。

## ドライバー {#driver-thisapp}

ドライバーはどのテストランナーでも同じオブジェクトです。違うのはテストがそれを受け取る方法だけです。

<CodeGroup>
```ts Vitest
import { test } from '@quiesco/vitest';

test('a new todo appears in the list', async ({ app }) => {
  await app.tap('add-todo');
});
```
```js Jest
test('a new todo appears in the list', async () => {
  await quiesco.app.tap('add-todo');
});
```
```ts Cucumber
import { When } from '@cucumber/cucumber';
import type { QuiescoWorld } from '@quiesco/cucumber';

When('I add a todo', async function (this: QuiescoWorld) {
  await this.app.tap('add-todo');
});
```
</CodeGroup>

このセクションの例では、Vitestの形の`app`を使います。Jestでは`quiesco.app`、Cucumberのステップでは`this.app`と書いてください。

## すべての呼び出しはアプリを待つ {#every-call-waits}

すべてのメソッドは`async`です。実行の前に、アプリが**アイドル**になるまで待ちます。アイドルとは、保留中のタイマー、リクエスト、レンダリング、アニメーションがない状態です（[同期](./sync)）。アクションは完了後にもう一度待ちます。そのため、テストでsleepやポーリングをする必要はありません。

```ts
// タップは、新しい画面の遷移とリクエストが終わった時点で戻る
await app.tap('open-settings');

// そのため、これは新しい画面で実行される
await app.tap('dark-mode-switch');
```

アサーション（`expectVisible`、`expectText`など）も、呼び出しのタイムアウトまで、成り立つまで再試行します。

## すべての呼び出しが受け取るオプション {#call-options}

すべてのメソッドは、省略可能な最後の引数を受け取ります。

| オプション | デフォルト | 意味 |
|---|---|---|
| `timeoutMs` | `sync.timeoutMs`（10秒） | この呼び出しが待てる時間 |
| `sync` | `true` | `false`：この呼び出しの前後でアイドルを待たない。アニメーションが終わらない画面向け |
| `mode` | `actions.mode` | アクションのみ。`'native'`：実際のタッチとキーボード入力（iOS / Androidでは`@quiesco/native`を使用、Webではブラウザー）。`'js'`：コンポーネントのコールバック（`onPress`、`onChangeText`）を呼ぶ |

```ts
// 遅い画面：最大30秒待つ
await app.expectVisible('report', { timeoutMs: 30_000 });

// この画面ではアニメーションがループしている：アイドルを待たない
await app.tap('stop-animation', { sync: false });

// 画面をタッチする代わりにonPressを呼ぶ
await app.tap('hidden-debug-button', { mode: 'js' });
```

## 要素を見つける {#finding-elements}

ほとんどのメソッドは**ターゲット**、つまり操作する要素を受け取ります。文字列は`testID`です。オブジェクトでは、テキスト、ロール、位置などの条件を組み合わせます。[マッチャー](./api-matchers)を参照してください。

```ts
await app.tap('save');
await app.tap({ role: 'button', text: 'Save' });
await app.expectText({ id: 'todo-title', index: 0 }, 'Buy milk');
```

アクションには、**表示されている**要素がちょうど1つ必要です。ターゲットが存在して表示されるまで待ち、時間内に現れなければ`ELEMENT_NOT_FOUND`で失敗します（メッセージには、存在しないのか隠れているのかが示されます）。複数の要素がマッチした場合は直ちに`MULTIPLE_MATCHES`で失敗します。`native`モードでは、タッチが要素に届くことも必要です。ダイアログや別のビューが要素を覆っている場合や、タッチする位置がスクロールビューに切り取られている場合、アクションは`ELEMENT_OBSCURED`で失敗し、何が邪魔をしているかを示します。ソフトウェアキーボードがターゲットを覆っている場合は、先にキーボードを閉じます。
