---
title: "同期"
description: "アイドルとは何か、それを判定するトラッカー、そしてアプリがいつまでもアイドルにならないときの対処。"
---

Quiescoは、すべてのクエリとアサーションの前、そしてすべてのアクションの後に、アプリが**アイドル**になるのを待ちます。そのため、ステップでsleepやポーリングをする必要はありません。「アイドル」はアプリ内で独立した複数のトラッカーが判定します。すべてのトラッカーが、マクロタスク1つ分を空けて2回続けてアイドルだったとき、アプリはアイドルとみなされます（タイマーが発火して同じtickでリクエストを開始しても、すり抜けることはありません）。

## トラッカー {#trackers}

| トラッカー | ビジーになる条件 | 補足 |
|---|---|---|
| `network` | `fetch` / `XMLHttpRequest`が実行中、レスポンスボディを読み込み中、または`WebSocket` / `EventSource`が接続中 | `fetch`はレスポンスが届くまでカウントされます。その直後に開始したボディの読み込み（`json()`、`text()`など）はボディが揃うまでビジーを維持し、後から読み込むと再びカウントされます。直接importした`expo/fetch`も追跡されます（e2eビルドでは`withQuiesco()`が追跡用の再エクスポートに差し替えます）。`WebSocket` / `EventSource`は、開くか、失敗するか、閉じるまでの間だけカウントされます。開いたままの接続はカウントされません（エージェント自身の接続も同様です）。`sync.ignoreUrls`でロングポーリング、SSE、アナリティクスを除外できます。XHR上に実装された`fetch`（React Native）は1回だけカウントされます。 |
| `timer` | 遅延が`sync.timerThresholdMs`（1.5秒）以下の`setTimeout`が保留中 | それより長いタイマー（セッションの有効期限、30秒ごとのポーリング）はブロックしません。`setInterval`は`sync.countIntervals: true`のときだけカウントされます。 |
| `react` | Reactに未コミットの作業がある：保留中のレーンやスケジュール済みのコールバックを持つルート、またはReactのスケジューラーに保留中のタスク（レンダリング作業、パッシブエフェクト） | DevToolsフック経由でReact自身の管理情報を読み取ります。アプリ側の変更は不要です。 |
| `idle-callback` | `requestIdleCallback`が保留中（`InteractionManager`がまだあるReact Nativeのバージョンでは、その作業も） | |
| `native`（iOS） | ビューコントローラーの遷移（ナビゲーション、モーダル表示）が実行中、またはキーボードが動いている / 使われた直後 | `@quiesco/native`が報告します。JavaScriptからは見えないUIKitの処理をカバーします。「キーボードが動いている」はUIKitの`keyboardWill…`通知から対応する`keyboardDid…`までで、長くてもアニメーション時間に0.5秒を足した時間です。iOSはキーボードがすでに表示されているのに`keyboardDidShow`を数秒遅れて送ることがあります（そのときデバイスログに`[Quiesco] keyboard: no Did notification …`が出ます）。 |
| `frame-stable` | 要素ツリー（すべての要素の型、testID、テキスト、丸めた位置とサイズ）が直近の`sync.stableFrames`（2）フレームの間に変化した | UIスレッド上のアニメーション（Reanimated、native driverの`Animated`）のためのフォールバックです。呼び出しが待機している間だけサンプリングされます。 |

| `native-module`（ネイティブモジュールをラップするビルドではオン） | ネイティブモジュールのメソッド（TurboModule / NativeModules、Expoモジュール）が返したPromiseが未解決。最長`sync.nativeCallThresholdMs`（2秒） | [ネイティブモジュールの呼び出し](#native-module-calls)を参照してください。 |

トラッカーをオフにするには`sync: { trackers: { 'frame-stable': false } }`とします。

タイムラインの各呼び出しには、アイドル待ちが最後に何を待っていたかがトラッカーごとに書かれます（`native-module: RNCDatePicker.open() 1990ms`、`network: GET https://api.example.com/items (240ms)`）。操作が想定より遅いときは、まずここを見てください。

### ネイティブモジュールの呼び出し {#native-module-calls}

`native-module`トラッカーがないと、ネイティブモジュールの呼び出しが未完了でもアプリはビジーになりません。追跡される2つの処理のあいだでネイティブ呼び出しをawaitするハンドラーは、そのあいだアイドルに見えます。

```ts
// fetch：追跡される
await api.login(email, password);

// ネイティブモジュールのPromise：既定では追跡されない
await AsyncStorage.setItem(TOKEN_KEY, token);

// 次の画面がマウントされ、effectでfetchする
router.replace('/');
```

`tap('login-submit')`は、`setItem`の完了前、つまり画面遷移と次の画面のリクエストが始まる前に戻ることがあります。次のステップが必要とするものを待つ（`await app.expectVisible('item-row-1')`）か、ネイティブモジュールをラップしてビルドしてください。`metro.config.js`の`withQuiesco()`に`nativeModules: true`を渡し（またはMetroを`EXPO_PUBLIC_QUIESCO_NATIVE_MODULES=1`付きで起動し）、Metroを再起動します。

```js
module.exports = withQuiesco(getDefaultConfig(__dirname), { nativeModules: true });
```

このビルドでは`native-module`トラッカーがオンになり、ほかの設定は要りません。設定項目は次のとおりです。

```ts
sync: {
  // 未完了の呼び出しをビジーとみなす上限
  nativeCallThresholdMs: 2000,

  // "Module.method"。文字列は部分一致
  ignoreNativeCalls: ['ExpoLocation.watch'],

  // ラップするビルドでオフにする
  // trackers: { 'native-module': false },
}
```

ラップしない場合、エージェントはネイティブモジュールに手を加えず、トラッカーは何も数えません（このとき`trackers: { 'native-module': true }`と書くとアプリが警告を出し、`quiesco doctor`も警告します）。ラップするビルドでトラッカーをオフにした場合も、呼び出しは記録されます。未完了の呼び出しが残ったまま戻った操作は、タイムラインの項目にその呼び出しが書かれ、失敗したシナリオの`idle-state.json`にも直近のそうした操作が並びます（`nativeCallsNotCounted`）。この競合を疑う手がかりになります。ラップするとモジュールのメソッドがJSの関数に置き換わります。Gesture Handler、Reanimated、WorkletsはUIスレッドのworkletから自身のモジュールのメソッドを呼び出し、それにはネイティブの関数が必要なため、これらのモジュールはラップしません。

このトラッカーは、エージェントの読み込み後にアプリがReact Nativeの`TurboModuleRegistry`とExpo（`requireNativeModule`）から取得するモジュールをラップします。React Nativeが起動時に取得する自身のモジュールは追跡されません。権限のリクエスト、認証シート、ピッカーなど、ユーザーの操作を待つネイティブ呼び出しは、テストが応答するまで未完了のままです。次の呼び出しは既定でビジーとみなしません。Expoモジュールと`PermissionsAndroid`の権限リクエスト（`*.request…Permission(s)(Async)`）、日付・時刻ピッカーのダイアログ（`RNCDatePicker.open`、`RNCTimePicker.open`）、`ExpoLocalAuthentication.authenticateAsync`、共有シート（`ShareModule.share`、`ExpoSharing.shareAsync`）、`ExpoWebBrowser.openBrowserAsync` / `openAuthSessionAsync`、画像とドキュメントのピッカーです。`ignoreNativeCalls`はこれに追加され、`defaultIgnoreNativeCalls: false`にするとこれらもビジーとみなします。ほかの呼び出しは`nativeCallThresholdMs`を過ぎるとビジーとみなされなくなるので、そうしたUIを開くステップの待ち時間は最長でもその長さです。タイムラインにその呼び出しが出る（`native-module: Module.method() 1990ms`）ので、`ignoreNativeCalls`に加えてください。

Reactトラッカーの仕組みと、エージェントをReact Nativeのレンダラーより先に読み込む必要がある理由は、[docs/spikes/02-react-idle.md](https://github.com/h2nology/quiesco/blob/main/docs/spikes/02-react-idle.md)で説明しています。読み込み順は`metro.config.js`の`withQuiesco()`が面倒を見ます（React Native 0.88はアプリのエントリーファイルより先にレンダラーを読み込みます）。

## アプリがいつまでもアイドルにならないとき {#when-the-app-never-becomes-idle}

`sync.timeoutMs`（10秒）より長く待った呼び出しは`SYNC_TIMEOUT`で失敗し、何がビジーだったかを列挙します。

```
App did not become idle within the 10000ms timeout. Busy:
  - network: GET https://api.example.com/todos (10012ms)
  - timer: setTimeout(poll, 1000ms), fires in 420ms
  - frame-stable: element tree changing: stable for 1/2 frames (580 frames sampled in 9960ms)
    last change: first difference at node 12: Text "Loading 41%" … → Text "Loading 42%" …
```

対処はトラッカーによって異なります。

- **network**：終わらないリクエスト（ロングポーリング、応答が止まったバックエンド）です。`sync.ignoreUrls`に追加するか、バックエンド / モックを修正します。意図的に再現するには、モックサーバーに`MOCK_STALL`のような切り替えを用意します。
- **timer**：短いタイマーが延々と再設定されています（`setTimeout`によるポーリングループ、自分自身を再スケジュールするトースト）。そのステップの同期をスキップする（`{ sync: false }`）か、そのシナリオだけtimer trackerを止める（`this.app.sync.disableTracker('timer')`）か、e2eビルドではループを止めます。カウントされるのは遅延が`sync.timerThresholdMs`以下のタイマーだけなので、しきい値をループの間隔より下げても解消しますが、アプリ全体でそれより短いタイマーがすべて対象外になります。
- **frame-stable**：何かが動き続けています。終わらないアニメーション（スピナー、シマー、マーキー、ゆっくり動く装飾用の光）やカウンターです。レポートには最初に変化した要素が示されます。その要素が装飾であれば、testIDを付けて`sync.ignoreElements`に加えます。その要素とサブツリーはこのチェックから外れ、それ以外はこれまでどおりチェックされます。そうでなければ、そのステップを`{ sync: false }`付きで呼び出して、必要なことを後からアサートするか、e2eビルドではアニメーションを無効にします。待った時間に対して`frames sampled`が極端に少ない場合は、アニメーションではなくUIスレッドが処理しきれていない（エミュレーターが過負荷）状態です。`recent changes`には直近の変化（待機開始からの時間、ノード数、最初に異なるノード）が並びます。同じ要素が行ったり来たりの変化を続けている場合は、ツリーの他の部分が変わっていても、レポートにその要素が示されます。毎回要素が追加されては削除されているなら、たいていはリストです。`getItemLayout`がなく行の高さが少しずつ違う`FlatList` / `VirtualizedList`は、スクロールのあと描画ウィンドウの端の項目を追加しては削除し続けることがあります。`timeoutMs`を延ばしても解決しません。`getItemLayout`を指定するか行の高さを固定すると、たいてい止まります。実際に起きている処理なので、Quiescoはこれもビジーとして扱います。frame-stableは呼び出しが待機している間だけサンプリングするため、タイムアウト後の`idle-state.json`ではアイドルと表示されます。待機が終わった時点の報告内容は`lastWait`に残ります。
- **react**：レンダリングループ（ガードのないエフェクト内での状態更新）が収まらない状態です。実際のバグです。

`AGENT_TIMEOUT`は別物です。エージェントがまったく応答しなかったことを示し、たいていは長い同期処理でJSスレッドがブロックされています。

## 1回の呼び出しだけ同期をスキップする {#skipping-sync-for-one-call}

```ts
// 前後で待たない
await this.app.tap('start-spinner', { sync: false });

// 回っている間にアサートする
await this.app.expectVisible('spinner', { sync: false });
```

## プラットフォームごとの補足 {#platform-notes}

3つのプラットフォームすべてで同じトラッカーが動きます。Webでは、ページ全体の読み込み後にエージェントが再接続し、ホスト側はそれを意識させずに待ちます。Expo Routerの静的出力では、ハイドレーションの後にアプリの準備ができたとみなします。`native`トラッカーはiOSにしかありません。[プラットフォームの違い](./platforms)を参照してください。
