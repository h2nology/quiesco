---

Quiescoは、すべての呼び出しの前後でアプリが**アイドル**になるのを待ちます。テストに`sleep`や
`waitFor`は要りません。

```ts
// リクエスト、画面遷移、次の画面の描画を待つ
await app.tap('save-todo');

// 落ち着いた画面に対して実行される
await app.expectVisible('todo-list-screen');
```

## しくみ {#how-it-works}

<Steps>
  <Step title="待ってから操作する">
    呼び出しの前に、Quiescoはアプリがアイドルになるのを待ちます。それからタップ、入力、画面の読み取りをします。
  </Step>
  <Step title="アプリが反応する">
    呼び出しによって、アプリの中でリクエスト、タイマー、描画、アニメーションが始まります。
  </Step>
  <Step title="もう一度待つ">
    すべての[トラッカー](#trackers)がアイドルになるまで待ちます。1マクロタスク空けて2回続けて確認するので、同じtickでリクエストを始めるタイマーも見逃しません。それから呼び出しが戻ります。
  </Step>
</Steps>

`sync.timeoutMs`（10秒）を過ぎても待っている呼び出しは`SYNC_TIMEOUT`で失敗します（[後述](#when-the-app-never-becomes-idle)）。

## トラッカー {#trackers}

アプリ内のエージェントは、次のトラッカーで「アイドル」を判定します。どのトラッカーもビジーでなければ、アプリはアイドルです。

| トラッカー | ビジーになる条件 |
|---|---|
| `network` | `fetch`や`XMLHttpRequest`が進行中、または`WebSocket` / `EventSource`が接続中 |
| `timer` | 1.5秒以下の`setTimeout`が待機中 |
| `react` | Reactにまだ実行していない描画やeffectがある |
| `idle-callback` | `requestIdleCallback`が待機中 |
| `native`（iOSのみ） | 画面遷移やキーボードのアニメーション中 |
| `frame-stable` | 直近2フレームで画面が変化した：UIスレッド上のアニメーション |
| `native-module`（要オプトイン） | ネイティブモジュールの呼び出しが終わっていない。最大2秒（[詳細](#native-module-calls)） |

トラッカーを無効にするには：

```ts
sync: { trackers: { 'frame-stable': false } }
```

<AccordionGroup>
  <Accordion title="network">
    - `fetch`はレスポンスが届くまでビジーです。続けてボディを読む（`json()`、`text()`など）と、ボディを読み終えるまでビジーが続きます。
    - `expo/fetch`も追跡されます。XHRの上に作られた`fetch`（React Native）は1回だけ数えます。
    - `WebSocket` / `EventSource`は、開くか、失敗するか、閉じるまでだけビジーです。開いている接続は数えません。エージェント自身の接続も数えません。
    - `sync.ignoreUrls`で、ロングポーリング、SSE、アナリティクスを除外できます。
  </Accordion>
  <Accordion title="timer">
    - `sync.timerThresholdMs`（1.5秒）以下のタイマーだけを数えます。30秒のセッションタイムアウトは待ちません。
    - `setInterval`は`sync.countIntervals: true`のときだけ数えます。
  </Accordion>
  <Accordion title="react">
    - React DevToolsのフックを通して、React自身の記録（保留中のlane、予約されたコールバック、Reactスケジューラーのタスク）を読みます。アプリの側は何も変えなくて構いません。
    - エージェントは、React Nativeのレンダラーが読み込まれる前にこのフックを入れる必要があります。`metro.config.js`の`withQuiesco()`がこれを引き受けます。
  </Accordion>
  <Accordion title="native (iOS)">
    - `@quiesco/native`が報告します。ナビゲーションやモーダルの遷移など、JavaScriptからは見えないUIKitの処理です。
    - キーボードは、UIKitの`keyboardWill…`通知から対応する`keyboardDid…`まで、最長でアニメーション時間＋0.5秒ビジーです。iOSは`keyboardDidShow`を数秒遅れて送ることがあり、そのときデバイスログに`[Quiesco] keyboard: no Did notification …`が出ます。
  </Accordion>
  <Accordion title="frame-stable">
    - 要素ツリー（型、testID、テキスト、丸めた位置とサイズ）をフレームごとに比べます。直近`sync.stableFrames`（2）フレームで変化があればビジーです。
    - UIスレッドで動くアニメーション（Reanimated、ネイティブドライバーの`Animated`）は他のトラッカーには見えないので、その受け皿です。
    - 呼び出しが待っているあいだだけサンプリングします。
  </Accordion>
</AccordionGroup>

## 呼び出しが遅い、または早く戻りすぎるときは {#timeline}

`timeline.html`の各呼び出しのエントリーに、アイドル待ちの様子が出ます。

- **遅い呼び出し**：トラッカーごとに、待ちが何で終わったか。例：`network: GET https://api.example.com/items (240ms)`。
- **早く戻りすぎた呼び出し**：最後の確認の様子。例：`+272ms busy: native-module | +276ms idle | +277ms idle (confirmed)`。そのあいだに始まった、または終わったネイティブモジュールの呼び出しも出ます。時刻はデバイスの時計なので、デバイスログと突き合わせられます。

`SYNC_TIMEOUT`で失敗した呼び出しにも、`scrollTo`の各ステップにも、この記録があります。

## アプリがアイドルにならないとき {#when-the-app-never-becomes-idle}

呼び出しは`SYNC_TIMEOUT`で失敗し、ビジーだったものを一覧にします。

```
App did not become idle within the 10000ms timeout. Busy:
  - network: GET https://api.example.com/todos (10012ms)
  - timer: setTimeout(poll, 1000ms), fires in 420ms
  - frame-stable: element tree changing: stable for 1/2 frames (580 frames sampled in 9960ms)
    last change: first difference at node 12: Text "Loading 41%" … → Text "Loading 42%" …
```

ビジーだったトラッカーで表を引いてください。

| ビジー | よくある原因 | 対処 |
|---|---|---|
| `network` | 終わらないリクエスト：ロングポーリング、止まったバックエンド | URLを`sync.ignoreUrls`に加える。またはバックエンド / モックを直す |
| `timer` | 永遠にかけ直される短いタイマー：ポーリング、自分を予約し直すトースト | そのステップに`{ sync: false }`、`this.app.sync.disableTracker('timer')`、またはe2eビルドでループを止める |
| `frame-stable` | 終わらないアニメーション：スピナー、シマー、装飾的なグロー | その要素にtestIDを付けて`sync.ignoreElements`に加える |
| `react` | 描画ループ：ガードのないeffectでの状態更新 | 本物のバグなので直す |

<AccordionGroup>
  <Accordion title="レポートの読み方">
    - タイムアウトの少し前（1秒以内）までビジーで、その瞬間にはアイドルだったトラッカーも載ります：`frame-stable (idle at the timeout, busy 12ms before it): …`。「タイマー → 描画 → 静かな数フレーム」のループは一部の時間アイドルなので、タイムアウトがそこに当たることがあります。
    - `frame-stable`は最初に変化した要素を示し、`recent changes`は直近の変化を並べます。同じ要素が行ったり来たりしているときは、レポートがその要素を名指しします。
    - 待った時間に対して`frames sampled`がとても少ないなら、アニメーションではなく、UIスレッドが詰まっています（負荷の高いエミュレーター）。
    - タイムアウト後の`idle-state.json`では`frame-stable`がアイドルと表示されます。呼び出しが待っているあいだしかサンプリングしないためです。`lastWait`に、待ちが終わったときの報告が残っています。
  </Accordion>
  <Accordion title="落ち着かないリスト">
    `getItemLayout`がなく、行の高さが少しずつ違う`FlatList` / `VirtualizedList`は、スクロール後に描画ウィンドウの端の項目を追加しては削除し続けることがあります。レポートには、毎回追加と削除をくり返す要素が出ます。`timeoutMs`を延ばしても効きません。`getItemLayout`か固定の行の高さで、たいてい止まります。
  </Accordion>
  <Accordion title="その他の対処">
    - **timer**：`sync.timerThresholdMs`をループの間隔より小さくしても効きますが、アプリ全体のそれだけ短いタイマーすべてに影響します。
    - **frame-stable**：動いている要素が装飾でないなら、そのステップを`{ sync: false }`で呼び、あとで必要なことをアサートします。またはe2eビルドでアニメーションを止めます。
    - **network**：モックサーバーに`MOCK_STALL`のようなスイッチを用意すると、止まったバックエンドをわざと再現できます。
  </Accordion>
</AccordionGroup>

<Note>
  `AGENT_TIMEOUT`は別物です。エージェントがまったく応答しなかったことを表し、たいていは長い同期処理がJSスレッドをふさいでいます。
</Note>

## 1回の呼び出しだけ同期を省く {#skipping-sync-for-one-call}

```ts
// 前後で待たない
await this.app.tap('start-spinner', { sync: false });

// 回っているあいだにアサートする
await this.app.expectVisible('spinner', { sync: false });
```

## ネイティブモジュールの呼び出し {#native-module-calls}

デフォルトでは、終わっていないネイティブモジュールの呼び出し（AsyncStorage、ピッカーなど）はアプリをビジーにしません。そのため、操作が早く戻りすぎることがあります。

```ts
// fetch：追跡される
await api.login(email, password);

// ネイティブモジュールのPromise：デフォルトでは追跡されない
await AsyncStorage.setItem(TOKEN_KEY, token);

// 次の画面がマウントされ、effectでfetchする
router.replace('/');
```

`tap('login-submit')`は、`setItem`が終わる前、次の画面が始まる前に戻ることがあります。対処は2つです。

- 次のステップに必要なものを待つ：`await app.expectVisible('item-row-1')`。
- またはネイティブモジュールの呼び出しを追跡する：e2eビルドで呼び出しをラップし、Metroを再起動します。

```js
module.exports = withQuiesco(getDefaultConfig(__dirname), { nativeModules: true });
```

Metroの起動時に`EXPO_PUBLIC_QUIESCO_NATIVE_MODULES=1`を設定しても同じです。これで`native-module`トラッカーが有効になります。設定は次のとおりです。

```ts
sync: {
  // 終わっていない呼び出しを数える上限
  nativeCallThresholdMs: 2000,

  // "Module.method"。文字列は部分一致
  ignoreNativeCalls: ['ExpoLocation.watch'],

  // ネイティブモジュールをラップしたビルドで無効にする
  // trackers: { 'native-module': false },
}
```

<AccordionGroup>
  <Accordion title="数えない呼び出し">
    ユーザーの操作を待つ呼び出しは、テストが応答するまで終わりません。これらは数えません。

    - 権限リクエスト：Expoモジュールと`PermissionsAndroid`（`*.request…Permission(s)(Async)`）
    - 日付 / 時刻ピッカー：`RNCDatePicker.open`、`RNCTimePicker.open`
    - `ExpoLocalAuthentication.authenticateAsync`
    - 共有シート：`ShareModule.share`、`ExpoSharing.shareAsync`
    - `ExpoWebBrowser.openBrowserAsync` / `openAuthSessionAsync`
    - 画像とドキュメントのピッカー
    - アラートとアクションシート：`AlertManager.alertWithArgs`、`DialogManagerAndroid.showAlert`、`ActionSheetManager.show…ActionSheetWithOptions`
    - ネイティブドライバーのアニメーション（`NativeAnimatedModule`）

    `ignoreNativeCalls`はこの一覧に追加します。`defaultIgnoreNativeCalls: false`にすると、これらも数えます。それ以外の呼び出しは`nativeCallThresholdMs`を過ぎると数えなくなります。タイムラインに呼び出し名（`native-module: Module.method() 1990ms`）が出るので、`ignoreNativeCalls`に加えられます。

    イベントの購読（`addListener(eventName, listener)`、`add…Listener` / `remove…Listener(s)`）は、Promiseを返すときだけ数えます。`defaultIgnoreNativeCalls`の設定には関係しません。
  </Accordion>
  <Accordion title="ラップされないもの">
    - React Nativeの起動中、エージェントの読み込み前に取得されるモジュール：React Native自身のモジュール。ラップされるのは、その後に`TurboModuleRegistry`とExpoの`requireNativeModule`から取得されるモジュールだけです。
    - Gesture Handler、Reanimated、Worklets：UIスレッドのworkletから自分のモジュールを呼ぶため、ネイティブの関数のままである必要があります。
  </Accordion>
  <Accordion title="ラップしていない、またはトラッカーを無効にしたとき">
    - `nativeModules: true`がなければ、このトラッカーは何も数えません。そのとき`trackers: { 'native-module': true }`は警告を出し、`quiesco doctor`も警告します。
    - ラップしたうえでトラッカーを無効にした場合も、呼び出しは記録されます。呼び出しが終わる前に戻った操作はタイムラインのエントリーにそれを載せ、失敗したテストの`idle-state.json`にも載ります（`nativeCallsNotCounted`）。
  </Accordion>
</AccordionGroup>

## プラットフォームごとの注意 {#platform-notes}

- 3つのプラットフォームで同じトラッカーが動きます。`native`はiOSだけです。
- Web：ページ全体を読み直すとエージェントが再接続し、Quiescoはそれを待ちます。Expo Routerの静的出力では、ハイドレーションが終わるとアプリの準備が整います。

詳しくは[プラットフォームの違い](./platforms)を参照してください。
