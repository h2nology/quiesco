**Detox 20.51.4**との項目別の比較です（ドキュメントとソースは667efcb時点のもの、2026-11-08に確認）。Detoxの列は、そのドキュメント、ソース、Issueトラッカーから取ったもので、計測はしていません。Quiescoの列は計測済みです。各項目には、それを確認しているサンプルアプリのfeature（`examples/todo-app/features/`）またはユニットテストを記載しています。また、サンプルのスイート全体が3つのプラットフォームすべてで通っています（結果は末尾を参照）。

凡例：✓ 対応 · ✗ 利用不可 · — そのプラットフォームには該当しない · (iOS) / (Android) Detoxがそのプラットフォームでのみ対応。

## Detoxの課題と、Quiescoでの解決方法 {#detox-pain-points-and-what-quiesco-does-instead}

| 課題（Detox） | Quiesco | 確認結果（2026-11-11） |
|---|---|---|
| Expo SDK 56以降のAndroidでネットワーク同期が効かない：監視しているのはOkHttpだけだが、グローバルの`fetch`は`expo/fetch`になっている（#4973） | エージェントがJS側でリクエストを追跡する。グローバルの`fetch`、直接importした`expo/fetch`（Metroのリゾルバー）、`XMLHttpRequest`、WebSocket / EventSourceのハンドシェイクを、レスポンスボディを読み終えるまで追跡する | device: 等待 expo/fetch 的慢响应体, 离线时 expo/fetch 也失败, 等待 WebSocket 握手：iOS / Android / Web、リトライせずに結果を一度だけ読む |
| React Nativeのリリースで壊れる（RN 0.85.3のbridgelessでクラッシュ、#4963：プライベートフィールドへのリフレクション） | 要素はプライベートなネイティブのフィールドではなく、DevToolsフック経由でReact自身のツリーから見つける（1ファイル、`fiber-adapter`）。ネイティブモジュールは入力の注入だけを行う | React Native 0.88 / Expo SDK 58、bridgeless、3プラットフォームでスイート全体 |
| 同期が全か無か：終わらないアニメーション、ポーリング、ソケットでテストが止まる。抜け出すにはグローバルにオフにするしかない（#1513） | 実行時にトラッカー単位・要素単位で設定でき（`sync.disableTracker`、`ignoreElements`、`ignoreUrls`）、呼び出し単位でも`{ sync: false }`を指定できる。開いたままのWebSocketは数えず、ハンドシェイクだけを数える | lifecycle: 运行时只关闭定时器同步，并忽略轮询计数; device: 等待 WebSocket 握手 |
| `expect`が待たない。グローバルなタイムアウトがない（#4885） | アサーションは成立するまでリトライする。デフォルトは`sync.timeoutMs`、呼び出し単位で`timeoutMs` | webview: 等待网页里稍后出现的结果（およびすべてのアサーション） |
| iOSのキーボードが最初のタップを吸収する（#3399）。表示チェックのせいでリターンキーをタップできない（#4546） | 対象を覆うキーボードは先に閉じ、`native`トラッカーがキーボード操作後にiOSがタッチを受け付けない期間を待つ。`pressKey('enter')`はキーボードなしでフィールドに届く | login / new-todo（iOSで入力してからタップ）; new-todo: 在标题框按回车也能保存; actions: 键盘按键与替换文本 |
| WebViewの入力が不安定で、Androidで複数の問題がある（#4886） | 実際のタップの後に`execCommand('insertText')`で入力する。3つのプラットフォームで同じAPI | webview: 在网页里输入名字后打招呼, 替换输入框里的文字：iOS / Android / Web |
| 多くの機能がiOS限定（ピンチ、起動時の権限、生体認証、シェイク、ステータスバー、ロケール、システムUI、ピッカーの列） | いずれもiOSとAndroidで使え、ほとんどはWebでも使える（上の表を参照） | gestures, values, device, system |
| `atIndex`の順序がiOSとAndroidで異なる。`toBeVisible`は75%固定 | `index` = どこでもレンダリング順。表示判定は1ピクセルでも見えればよく、`ratio`は任意 | ユニットテスト（agent query、visibility） |
| `setTimeout`は1.5秒までしか待たず、`setInterval`は無視され、設定もできない | `sync.timerThresholdMs`（デフォルト1500）で設定可能。ビジーなタイマーはタイムアウトのエラーで名前が示される | ユニットテスト（timer tracker） |
| 別のテスト用APK、ProGuardのルール、フレームワークのキャッシュが必要 | config plugin経由のアプリのe2eビルド（`EXPO_PUBLIC_QUIESCO=1`）1つだけ。本番ビルドには何も含まれないことを検証済み | `scripts/check-prod-strip.mjs`（benchmarks.md） |
| Jestのみ。成果物のドキュメントは「to be done」 | Cucumber / Jest / Vitest。成果物もドキュメント化済み（api.md、Artifacts） | e2e/jest, e2e/vitest, features |

|---|---|---|

| `setColumnToValue`（ピッカー） | iOS | iOS、Android、Web |
| `pinch` | iOS | iOS、Android、Web（タッチ） |
| `by.traits` | iOS | `role` / セマンティックな`type`：iOS、Android、Web |

| `resetContentAndSettings` | iOS | iOS、Android、Webで呼び出しを組み合わせる |
| `captureViewHierarchy` | iOS | iOS、Android、Web |
| `shake` | iOS | iOS、Android |
| 生体認証 | iOS | iOS、Android |
| `setStatusBar` | iOS | iOS、Android（Webにはない） |
| `system.element` | iOS | iOS、Android、Web（JSのダイアログ） |
| `pressBack` | Android | Android、Web（iOSには戻るボタンがない） |
| `getUiDevice` | Android | `device.system`：iOS、Android、Web |
| `clearKeychain` | iOS | **iOSのみ**：AndroidとWebにはキーチェーンがない。そちらでは`relaunch({ clearData: true })`が相当する |
| `reverseTcpPort` | Android | Androidのみ：iOSシミュレーターとブラウザはホストのネットワークを共有するので、リバースするものがない |
| `sendUserActivity` / `userActivity` | iOS | 提供しない（未対応の項目） |

## 未対応の項目 {#gaps}

作らないと決めたもの（2026-11-11）と、その代替手段：

- **`selectApp`（1つのテストで複数のアプリ）：** 1セッションにつき1アプリです。アプリごとに別々に実行してください。
- **`sendUserActivity` / `launchApp({ userActivity })`：** Handoff / Spotlight / Siriのアクティビティはシミュレートしません。ユニバーサルリンクを含むリンクは`openUrl`または`relaunch({ url })`で開きます。
- **`resetContentAndSettings`：** シミュレーター全体の消去はありません。`relaunch({ reinstall: true })`でアプリとそのデータを削除し、`setPermission(p, 'reset')`で権限を「未決定」に戻し、`clearKeychain()`でキーチェーンを空にします。シナリオが変更したデバイスの状態（画面の向き、外観、ロケール、位置情報、ネットワーク、ステータスバー、生体認証）は、次のシナリオの前に自動的に元に戻ります。
- **`retries`：** ランナー自身のリトライオプションを使います。
- **`by.traits`：** `{ role }`とセマンティックな`{ type }`を使います。

延期したもの（2026-11-14）で、まだ作っていないもの：

- **実機（Phase 6.13）：** adb経由のAndroid実機とiOS実機は検証していません。シミュレーター、エミュレーター、Chromiumで実行してください。
- **LLMが駆動するステップ（Phase 6.14、Detox Pilot）：** 提供していません。Driver APIに対してステップを書いてください。
